## P0, D0, and D1

Each case ran in a fresh process with `--no-warmup` through
`test/profile/nsys_profile.py`.

| Case | Input | Requested output | Actual output | Wall time | Throughput | Wall time/output token |
| --- | ---: | ---: | ---: | ---: | ---: | ---: |
| P0 | 256 | 1 | 1 | 0.28 s | 3.6 tok/s | 280 ms |
| D0 | 1 | 128 | 75 | 1.81 s | 41.4 tok/s | 24.1 ms |
| D1 | 1024 | 128 | 128 | 3.85 s | 33.3 tok/s | 30.1 ms |

D0 stopped after 75 generated tokens on EOS; the public generation API does
not expose an ignore-EOS mode. It therefore records the exact baseline behavior
for a request capped at 128 rather than 128 completed decode iterations.

The existing serial benchmark supports absolute aggregate latency statistics.
For the three-prompt greedy run it reported:

- LLAISYS average latency: 435.4 ms
- TTFT: 113.7 ms
- TPOT: 27.24 ms
- Throughput: 36.7 tokens/s

`nsys_profile.py` does not expose per-request TTFT, so P0/D0/D1 TTFT is N/A.
P0's one-token wall time is the available end-to-end first-token proxy.

## Measurement limitations and concerns

- Measurements are single runs on a laptop GPU under WSL2, without power or
  clock locking; they are comparison anchors, not statistically stable claims.
- The standard `nvidia-smi` command is not on PATH in this WSL environment;
  environment data came from `/usr/lib/wsl/lib/nvidia-smi`.
- `test/test_tensor.py` has no device argument and exercises CPU tensor
  behavior. NVIDIA tensor movement is covered indirectly by the runtime and
  operator tests, but there is no dedicated NVIDIA tensor suite.
- This baseline has no direct standalone test for `kv_cache_move` or
  `rearrange`; both are exercised through model inference.
- A custom process that reused one model for P0, D0, then D1 hung after more
  than 12 minutes (4673 MiB allocated, 0% sampled GPU utilization, about 99%
  CPU). Each required case completed normally in a fresh process, which is the
  measurement protocol recorded above.
- D0 reached EOS after 75 tokens, as noted above.

5. capture the same `cuda_gpu_kern_sum` report and compare total launches,
   total kernel time, dominant kernel count/time, and end-to-end wall time;
6. retain raw reports under ignored scratch output and never commit profiler
   binaries, SQLite exports, or model artifacts.
