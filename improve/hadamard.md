# Hadamard 变换加速（CUDA）

最新研究表明，在量化前对激活进行随机旋转（如 Hadamard 变换）可以有效抑制异常值，提升低比特量化精度——这是 QuaRot、SpinQuant、FlashAttention-3 等前沿工作的核心思想。然而，Hadamard 变换本身引入了额外计算开销，可能抵消量化带来的收益。

公司要求你实现一个利用 Tensor Core 加速的 Hadamard 变换核，将旋转开销降至最低，使得 FP8/INT4 量化在保持精度的同时真正加速。

### 领域知识简介

Hadamard 变换的价值：神经网络激活中存在异常值，导致量化误差增大。

Hadamard 变换是一种正交变换，可以将异常值能量 “扩散” 到多个维度，降低单个维度的动态范围。QuaRot 和 SpinQuant 证明，在注意力计算前后插入 Hadamard 变换，可使 INT4/FP8 量化精度接近 FP16。更多详细信息需要各位学员自行调研。

### 任务内容

实现一个基于 Tensor Core 的快速 Hadamard 变换核，支持多种输入尺寸，并与量化算子融合。

### 输入文件定义
1. 一系列输入张量的形状与类型。输入张量：
[batch_size, seq_len, num_heads, head_dim]，FP16 或 BF16
- Hadamard 矩阵大小：head_dim（必须是 2 的幂次，如 64、128、256）
输出文件定义
- 性能日志：核函数执行时间（ms）。
要求
1. 功能正确性：
  - 对于 FP16，与参考实现（如 fast_hadamard_transform 库）的绝对误差小于 1e-2。
  - 对于 BF16，绝对误差小于 5e-2。
  - 当融合量化时，需验证量化后的结果与先变换后量化的结果一致。
2. Tensor Core：需使用 Tensor Core 进行加速。
